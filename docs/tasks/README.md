# タスク管理

## 基本方針

個人開発でも保守できるよう、状態と文書を増やしすぎません。`backlog.md` に未着手タスクの短い一覧を置き、背景・範囲・受け入れ条件を共有する必要があるタスクだけ個別文書を作ります。着手後も一覧と個別文書を二重に詳しく管理せず、一覧には ID、タイトル、状態、個別文書へのリンクを記載します。

初期状態では `backlog.md` や個別タスク文書がまだない場合があります。必要なタスクを追加するときに作成してください。

## 個別タスク文書

ファイル名は `T-001-short-title.md` のように、重複しない ID と短い英小文字タイトルを使います。タスクには次の項目を含めます。

```markdown
# T-001: タイトル

- 状態: Backlog
- 担当AI: Cursor Agent / Codex CLI / ChatGPT / Claude / 人間（該当するもの）
- 関連レビュー: なし、またはレビュー記録へのリンク

## 背景・目的

## 作業範囲

## 対象外

## 依存関係
- なし、または先行タスク・決定事項へのリンク

## 要確認事項
- なし、または質問と確認状況

## 受け入れ条件
- [ ] 満たすべき結果を確認可能な形で記載

## 検証方法
- 実施するテスト、静的解析、手動確認を記載
```

該当しない項目も削除せず「なし」と記載すると、確認漏れを避けられます。受け入れ条件は実装方法ではなく、完了を判断できる結果として書きます。

## 状態

状態は次の4つだけを使います。

- `Backlog`: 未着手
- `In Progress`: 作業中
- `In Review`: 実装後のレビュー中
- `Done`: 受け入れ条件と必要なレビューを確認済み

状態は個別タスク文書を正として管理し、一覧にも同じ状態を反映します。完了扱いにする前に、受け入れ条件、検証結果、レビュー指摘の対応状況を確認します。レビューが不要なタスクではその旨を明記します。

## AI 間の引き継ぎ

- ChatGPT は方針策定、タスク分解、設計レビューを担当します。
- Claude は `design-mockup/` に静的 HTML/CSS/JavaScript のモックアップを制作します。モックアップは人間のデザイン承認後に内容を検討し、テーマ本体へそのままコピーせず実装に反映します。
- Cursor Agent は主な実装を担当します。
- Codex CLI は独立レビューと品質確認を担当し、必要に応じて人間の依頼の範囲で実装支援します。

担当 AI はタスクの担当欄で明確にします。引き継ぎでは会話の共有を前提にせず、タスク文書、関連設計、変更差分、レビュー記録を渡します。開始、デザイン承認、レビュー結果、最終変更は人間が確認します。自動承認・自動統合は行いません。

## 完了時

タスク文書を更新し、受け入れ条件の結果、実施した検証と結果、未実施事項と理由、未解決の要確認事項、関連レビューを記録します。バックログ一覧の状態も同期します。
