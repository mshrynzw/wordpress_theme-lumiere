# LUMIÈRE サイト要件

- 状態: 初期要件確定（実店舗データ・公開先の入力待ち）
- 最終更新: 2026-10-25
- 根拠: 人間が確認した選択事項、未決事項について委任を受けて定めた初期方針、現行 `AGENTS.md` / `docs/README.md`

この文書は、LUMIÈRE の美容院サイト制作に向けた初期要件をまとめます。実店舗の事実は推測で作らず、架空の仮データを公開前に正確な情報へ差し替える前提です。

## 1. サイトの目的と対象

### 決定

- 美容院の新規ウェブサイトを制作する。既存サイトはない。
- 主な対象は地域住民・来訪者のうち、美容、ヘアカット、メイクに関心のある人。特定の年齢・性別には限定しない仮方針とする。
- 目的の優先順位は、認知向上を最優先、予約獲得を次点とする。
- 来店案内、メニュー・料金の確認、美容院の雰囲気や技術の紹介も行う。
- 初期公開は日本語とし、必要に応じて将来ほかの言語を追加できるようにする。
- 少人数のチームがサイトを運営・更新する。

### 実データに関する前提

- 来店エリア、店舗名、所在地、営業時間、連絡先、料金などの実店舗情報は未提示。
- カット・ヘアスタイル、カラー・パーマ、スタッフ・接客・店内の雰囲気は紹介内容の候補であり、実店舗の確定した強みではない。
- デザイン・開発中は架空の店舗情報と仮素材を使用する。実際の店舗情報・素材はテーマコードに固定しない。
- 初期公開は日本語のみとする。テーマ内の固定文言は翻訳可能な形で実装し、将来の翻訳追加を妨げない。初期公開に多言語プラグインは導入しない。

## 2. ページ構成

次のページを用意する。

| ID | ページ | 掲載内容の要件 |
|---|---|---|
| A | ホーム | 店舗の紹介、ヘアスタイル、人気メニュー、スタッフ、お知らせ、コラム、アクセスへの案内、予約導線。ヘアスタイル写真を主役にしたメインビジュアルを置き、「ヘアスタイルを見る」を主ボタン、「予約する」を副ボタンとして近くに配置する。 |
| B | ヘアスタイル | 施術写真、スタイル名、説明。施術メニューや髪の長さ等で分類・検索でき、おすすめスタイルを掲載できる。 |
| C | メニュー・料金 | 分類、メニュー名、説明、料金、所要時間、注意事項。料金表示はメニューごとに固定額・「〜」・価格幅を設定できる案とする。 |
| D | スタッフ | 写真、名前、紹介文、得意な施術。スタッフごとに掲載・非掲載を設定できる。SNSリンクは任意。 |
| E | 美容院について | コンセプト、店舗の特徴、接客や店内の雰囲気、店内写真。 |
| F | 店舗情報・アクセス | 店名、住所、営業時間、定休日、電話番号、アクセス説明、地図リンク。駐車場等の追加情報を掲載できる。 |
| G | 予約 | 電話、外部予約サービス、LINEまたはSNSへの案内。予約方法ごとに表示、説明、リンク、表示順を設定できる案とする。 |
| H | お知らせ | タイトル、本文、掲載日。分類、画像、掲載終了日を設定でき、ホームに最新情報を表示できる。 |
| I | ヘアケア・美容コラム | 記事本文、タイトル、公開日、画像、分類。執筆スタッフや関連メニューへのリンクは任意。 |
| J | よくある質問 | 質問、回答、分類、表示順。 |
| K | プライバシーポリシー | 本文を管理画面で編集できるページ。実際の情報利用方法に合わせた内容を掲載する。 |

ページ種別は11種類とする。お知らせとコラムには一覧・詳細の両方を設けるため、モックアップでは合計13種類の画面テンプレートを扱う。

### ナビゲーション案

- ヘッダーには、ヘアスタイル、メニュー、スタッフ、美容院について、お知らせ、コラム、店舗情報を配置する。
- 予約ボタンを目立つ形で設ける。
- ホームはロゴから移動できるようにする。
- よくある質問とプライバシーポリシーはフッターに配置する。

## 3. WordPress管理とテーマのカスタマイズ

### 決定

- 店舗情報、メニュー、スタッフ、スタイル写真、お知らせ、コラム、FAQ、各ページの文章・画像、予約先はWordPress管理画面から編集できるようにする。
- 画像には管理画面から代替テキストを設定できるようにする。
- ページ本文、繰り返し登録する情報、共通の店舗情報を適切に使い分ける。
- WordPress標準機能を基本とし、必要な機能だけ保守されているプラグインを追加する。
- テーマ固有の見た目の調整項目は必要な範囲に絞る。

### 投稿・固定ページの使い分け（決定）

- お知らせと美容・ヘアケアコラムは、WordPress標準の「投稿」で管理する。記事詳細は投稿ページ、一覧は投稿のアーカイブとして扱う。
- ホーム、美容院について、店舗情報・アクセス、メニュー、スタッフ、ヘアスタイル、予約、FAQ、プライバシーポリシーの案内・一覧画面は、WordPress標準の「固定ページ」を基本にする。
- メニュー、スタッフ、ヘアスタイル、FAQなど繰り返し登録する項目は、固定ページ本文に一件ずつ埋め込まず、独立した項目として登録・管理する。
- 独立項目はカスタム投稿タイプとして登録する。その登録機能はLUMIÈREテーマに含める。
- カスタム投稿タイプの入力項目、分類、並べ替え、テンプレートとの連携方法は技術設計で決める。
- テーマを切り替えてもカスタム投稿タイプのデータはデータベースに残るが、別テーマでは管理画面や表示に現れなくなる。LUMIÈREテーマを再度有効にすると登録機能が戻る。この制約をコンテンツの可搬性に関する例外として合意する。

### メニューの価格・分類（決定）

- メニュー名、分類、価格を基本項目とする。説明文と所要時間は任意項目とし、おすすめ表示、表示順、公開状態を設定できるようにする。
- 任意項目が未入力の場合は、サイト上に空欄の表示を出さない。
- メニューの価格表示は、固定価格、「○円〜」の開始価格、価格帯に対応する。
- 消費者向けの掲載価格は税込総額表示を基本とし、店舗責任者が実際の価格・税表示を公開前に確認する（[国税庁・総額表示](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shohi/6902.htm)）。
- 髪の長さ別・担当者別などの細かな価格バリエーションは今回の対象に含めず、必要性が確認された場合に再検討する。
- メニューの分類は管理画面から追加・編集できるようにする。初期分類はカット、カラー、パーマ、トリートメント、ヘッドスパとする。
- 分類の表示順を管理できるようにする。

### スタッフの登録項目（決定）

- 必須項目は氏名、写真、紹介文とする。写真には代替テキストを設定できるようにする。
- 役職・肩書き、得意な施術・スタイル、経歴・資格、個人SNSは任意項目とする。
- 得意な施術・スタイルはメニュー分類を共用し、スタッフごとに複数選択できるようにする。管理画面で追加された分類も選択肢に含める。
- 任意項目が未入力の場合は、サイト上に空欄の表示を出さない。
- スタッフ一覧の表示順と公開・非公開を管理できるようにする。
- 勤務シフトと個人の連絡先はスタッフプロフィール項目に含めない。

### ヘアスタイルの登録項目（決定）

- 各スタイルにタイトル、写真、代替テキストを登録する。
- スタイル説明、髪の長さ、スタイル分類、おすすめ表示、表示順、公開状態を管理できるようにする。
- 髪の長さとスタイル分類は、どちらも管理画面から追加・編集できるようにする。
- 初期の髪の長さはショート、ボブ、ミディアム、セミロング、ロングとする。初期のスタイル分類はレイヤー、パーマ、ストレート、前髪、メンズとする。
- 担当スタッフと関連メニューは任意で紐付けられるようにする。
- 分類の追加・並べ替えの編集方法と、スタッフ・メニューとの関連付けの入力方法は技術設計で決める。

### FAQの登録項目（決定）

- 各FAQに質問、回答、分類、表示順、公開状態を設定する。
- 回答には複数段落の文章とリンクを入力できるようにする。
- FAQの分類は追加できるようにし、分類名は固定しない。
- 関連メニューや予約ページへのリンクは任意項目とする。

### 編集場所の分け方（決定）

- 店舗共通情報は、専用の設定画面で一元管理し、必要なページ・領域に共通表示する。
- 共通情報には店舗名、郵便番号、住所、電話番号、営業時間、定休日、最寄り駅・道順、駐車場、支払い方法、地図情報、予約先URL、SNSアカウントURLを含める。
- 共通情報の設定画面はLUMIÈREテーマに含め、WordPress Options APIで保存する。テーマを切り替えた場合も保存値は残るが、設定画面はLUMIÈREを再度有効化するまで利用できない。
- SNS・予約方法の情報を登録する場所と、サイト上で表示するかどうかのテーマカスタマイズ設定は分ける。
- 固定ページ固有の案内文・画像は各固定ページで管理し、メニュー・スタッフ等の独立項目の文章・画像は各項目の編集画面で管理する。
- ロゴ、配色、ヘッダー・フッターの共通表示、ホームセクションの表示・順序、アニメーションなど、テーマの見た目や表示方法に関する設定はテーマカスタマイズで管理する。
- 営業時間は曜日ごとに複数の開店・閉店時間帯を登録可能とし、休業日・臨時休業の案内は別途入力できる構成とする。店舗ごとの特別な例外は実店舗情報を登録する段階で扱う。
- 地図は住所・アクセス説明に加え、外部地図サービスへのリンクを基本とする。埋め込み地図は必要性とプライバシー影響を確認してから追加する。
- 共通情報設定画面の具体的な項目配置、営業時間の入力UI、項目ごとの入力欄・分類・並べ替え方法は技術設計で定める。

### 管理機能の実装方針（決定）

- 外部のカスタムフィールド用プラグインには当初依存せず、WordPress標準機能を中心に管理画面を実装する。
- カスタム投稿タイプと専用の入力欄はLUMIÈREテーマに実装し、項目固有の構造化データはWordPressの投稿メタ情報として管理する。
- 各投稿タイプは、標準のタイトル・本文・アイキャッチ画像を基本にし、項目固有の構造化データは登録済み投稿メタ情報と専用入力欄で管理する。分類はWordPressのタクソノミーを使う。
- 共通店舗情報の設定画面はSettings APIとOptions API、テーマの外観・表示設定はCustomize APIを基本にする。
- 標準機能だけでは必要な編集操作や表示を実現しにくいことが分かった場合は、プラグイン導入を改めて検討する。
- 設定画面とテーマカスタマイザーは管理者権限を必要とする。編集者は投稿、固定ページ、カスタム投稿タイプ、メディアの編集を行えるようにする。
- 共通情報設定画面もLUMIÈREテーマ内に実装する。Options APIの保存値はテーマ切替後も残るが、画面はLUMIÈREを再度有効にするまで利用できない。この制約をカスタム投稿タイプと同様に許容する。
- データキー、入力欄の具体的な構成、権限割り当て、保存時の検証方法は技術設計で定める。

### テーマカスタマイズで扱う設定（決定）

- ロゴ
- 配色
- ヘッダー・フッターの表示設定
- ホームのセクション表示と順序
- ヒーロー写真（管理画面の運用上の固定枚数上限を設けず登録し、6.5秒間隔・1.1秒のフェードで切り替える。停止・再開と写真選択も可能にする。動きを減らす設定または非表示タブでは自動切替を止める）
- SNSごとの表示ON/OFF
- SNSの初期対応先はInstagram、LINE、YouTube、X、TikTok、Threads、Facebook、Pinterestとする。任意のSNS名・URLを追加できる汎用リンクも用意する。
- アニメーション設定

店舗共通情報、各固定ページの案内文、メニュー・スタッフ・ヘアスタイル・FAQの各項目の内容はテーマカスタマイズに置かず、それぞれのコンテンツ管理画面で編集する。

店舗の内容・文章・写真はテーマの表示コードに直接固定せず、WordPress上のコンテンツとして管理する。カスタム投稿タイプと共通設定画面の登録機能をテーマに含めるため、別テーマへ切り替えた場合の管理・表示には上記の制約がある。具体的な入力欄、データ構造、テンプレートとの連携方法は技術設計で定める。

## 4. デザイン・操作性

### 決定

- 全体の雰囲気はナチュラルで親しみやすい。
- 基調色はアイボリー `#FBF7F0`、リネン `#F2EADD`、サンド `#DDCCB3`、ウォルナット `#6B4A33`、ココア `#3A2A20`とし、差し色にくすんだ緑 `#5F6649`を使う。
- 見出しはShippori Mincho、本文はZen Kaku Gothic Newを使用する。
- ヘアスタイル写真と店内・スタッフ写真を組み合わせる。
- ホームは写真を印象的に見せ、各ページは情報を整理する。
- スマートフォンを優先して設計する。
- Claude向けモックアップはA〜Kの全11ページを対象とする。全ページをレスポンシブにし、ホームと代表的な下層ページはスマートフォン・PCの両方で重点確認する。
- ホームの最初の画面ではヘアスタイル写真を主役にし、主ボタンは「ヘアスタイルを見る」、副ボタンは「予約する」とする。
- 表示演出として、スクロール時の表示、背景の奥行き、横送りのスタイルギャラリーを組み合わせる。
- 端末で動きを減らす設定が有効な場合はアニメーションを控える。

### 要件上の留意点

アニメーションは選択したデザイン表現として扱う。操作や情報理解を妨げず、動きを減らす設定でも主要な情報と機能を利用できるようにする。

## 5. アクセシビリティ、パフォーマンス、検索

### アクセシビリティ

WCAG 2.2 AAを実装目標とする。これは目標であり、第三者による適合認証を意味しない。キーボード操作、フォーカス可視性、コントラスト、画像の代替テキスト、見出し構造、タッチ操作、動きを減らす設定を確認する。W3Cは新規・更新サイトにWCAG 2.2を採用することを推奨している（[WCAG 2.2](https://www.w3.org/TR/wcag/)）。

### パフォーマンス

画像を適切な寸法・容量にし、レスポンシブ画像と遅延読み込みを使う。公開後の実利用データでは、モバイル・デスクトップ別に75パーセンタイルでCore Web Vitalsの「良好」を目標とする（LCP 2.5秒以下、INP 200ミリ秒以下、CLS 0.1以下）。公開前はLighthouse等のラボ測定で重大な遅延・操作不能・レイアウト移動がないことを確認する。実利用データが不足する間はラボ結果を暫定基準とする（[Web Vitals](https://web.dev/articles/vitals)）。

### 検索対策

ページごとのタイトルと説明、画像の代替テキストを設定可能にする。店舗共通情報に基づく美容院のローカルビジネス情報を構造化データとして出力し、WordPress標準のサイトマップを利用する。専用SEOプラグインとアクセス解析ツールは初期公開では導入しない。

## 6. 予約、個人情報、管理権限

- サイト内の問い合わせフォーム・予約フォームは設けない。
- 予約導線は電話、外部オンライン予約、LINEを初期対応先とし、各方法の表示・説明・リンク・順序を管理できるようにする。SNS等の追加リンクにも対応する。実店舗が利用しない方法は非表示にする。
- 担当者ごとにWordPressアカウントを作成する。日常的な記事・固定ページ・メニュー・スタッフ等の更新は編集者権限、テーマカスタマイズと店舗共通設定は管理者権限を基本とする。
- 外部の予約サービスやSNSが個人情報を扱う場合、プライバシーポリシーの記載内容は実際の運用を確認して決める。

## 7. 技術・対応環境

- テーマ形式はクラシックテーマ。
- テーマの最低対応環境はWordPress 7.1以上、PHP 8.3以上、MySQL 8.0以上とし、本番はHTTPSを必須とする。WordPress.orgの現行推奨要件に合わせ、PHP 8.3以上・MySQL 8.0以上を基準とする（[WordPress requirements](https://wordpress.org/about/requirements/)）。
- 現在のLocal環境（WordPress 7.1.3、PHP 8.2.29、MySQL 8.4.0）は記録済みの開発環境であり、PHP 8.3以上の公開要件に対する追加確認環境は公開前に用意する。
- デスクトップのChrome、Edge、Firefox、Safari、およびiOS Safari・Android Chromeの現行安定版を対象にする。Internet Explorerは対象外とする。公開前に実機または同等のブラウザ環境で主要ページと予約導線を確認する。
- プラグインはWordPress標準機能を基本とし、必要なものに限る。
- 開発環境の記載値はプロジェクト文書に基づく。実稼働環境の状態はこの要件書では検証していない。

## 8. テスト、公開、運用

公開・運用は次の基準で行う。

- ステージング環境を本番と同等のPHP・WordPress条件で用意し、全ページ種別、主要画面幅、キーボード操作、管理画面での登録・更新、すべての有効な予約・SNSリンクを公開前に確認する。
- 本番反映はステージング確認後に人間が承認する。公開直後に主要ページ、HTTPS、予約導線、フォーム不在、SNS表示を再確認する。
- データベースとアップロードファイルを毎日バックアップし、更新作業前にもバックアップする。日次バックアップは最低30日保持し、復元確認を公開前および四半期ごとに行う。
- WordPress本体・テーマ・プラグインの更新を毎月確認し、セキュリティ修正はバックアップ後にステージングで確認して速やかに反映する。
- 具体的なホスティング会社と、そのバックアップ・ステージング機能の利用可否は契約前に要件適合を確認する。

## 10. 次の作業案

デザインモックアップは作成済みで、ユーザー確認により完成とする（[`design-mockup/README.md`](../design-mockup/README.md)）。以後は承認済みデザインを基準として、テーマ用に設計・実装し直す。

1. 決定済みの投稿タイプ、入力項目、共通設定画面、テーマカスタマイズを、データ構造・分類・関連付け・権限を含む技術設計に落とし込む。
2. クラシックテーマの構成、テンプレート、データ連携、画像登録・表示を設計し、アクセシビリティとパフォーマンスの目標を検証可能な確認項目にする。
3. WordPress 7.1以上・PHP 8.3以上の検証環境を用意し、合意した設計に基づいてテーマを実装・検証する。
4. 公開前に実店舗情報・素材・プライバシーポリシーを確定し、公開準備基準に従って確認する。

## 11. 公開前に必要な実データ・契約情報

以下は要件上の選択待ちではなく、実店舗の事実確認または外部契約が必要な公開準備項目とする。仮データを実データとみなして公開しない。

- 店舗の正式名称、所在地、営業時間、定休日、電話番号、実際のメニュー・料金、店舗の特徴、スタッフ情報
- 実際に利用する予約方法と予約先URL。利用しない予約方法は非表示にする。
- 店舗ロゴ、実写真、紹介文、プライバシーポリシーの確定文面。プライバシーポリシーは実際の個人情報の取扱いに合わせて店舗責任者が確認する。
- PHP 8.3以上、MySQL 8.0以上、HTTPSとステージング・バックアップ要件を満たすホスティング環境の契約・接続情報
