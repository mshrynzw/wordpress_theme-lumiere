# LUMIÈRE サイト要件（初稿）

- 状態: 要件定義中
- 最終更新: 2026-10-25
- 根拠: 人間が確認した会話上の選択事項と、現行 `AGENTS.md` / `docs/README.md`

この文書は、LUMIÈRE の美容院サイト制作に向けて現在合意している要件をまとめます。未確認の店舗情報や技術選択を事実として補わず、仮置き・要確認として記載します。

## 1. サイトの目的と対象

### 決定

- 美容院の新規ウェブサイトを制作する。既存サイトはない。
- 主な対象は地域住民・来訪者のうち、美容、ヘアカット、メイクに関心のある人。特定の年齢・性別には限定しない仮方針とする。
- 目的の優先順位は、認知向上を最優先、予約獲得を次点とする。
- 来店案内、メニュー・料金の確認、美容院の雰囲気や技術の紹介も行う。
- 初期公開は日本語とし、必要に応じて将来ほかの言語を追加できるようにする。
- 少人数のチームがサイトを運営・更新する。

### 仮置き・要確認

- 来店エリア、店舗名、所在地、営業時間、連絡先、料金などの実店舗情報は未提示。
- カット・ヘアスタイル、カラー・パーマ、スタッフ・接客・店内の雰囲気は紹介内容の候補であり、実店舗の確定した強みではない。
- デザイン確認用には架空の店舗情報と仮素材を使用できる。実際の店舗情報・素材はテーマに固定しない。

## 2. ページ構成

次のページを用意する。

| ID | ページ | 掲載内容の要件 |
|---|---|---|
| A | ホーム | 店舗の紹介、ヘアスタイル、人気メニュー、スタッフ、お知らせ、コラム、アクセスへの案内、予約導線。ヘアスタイル写真を主役にしたメインビジュアルを置き、「ヘアスタイルを見る」を主ボタン、「予約する」を副ボタンとして近くに配置する。 |
| B | ヘアスタイル | 施術写真、スタイル名、説明。施術メニューや髪の長さ等で分類・検索でき、おすすめスタイルを掲載できる。 |
| C | メニュー・料金 | 分類、メニュー名、説明、料金、所要時間、注意事項。料金表示はメニューごとに固定額・「〜」・価格幅を設定できる案とする。 |
| D | スタッフ | 写真、名前、紹介文、得意な施術。スタッフごとに掲載・非掲載を設定できる。SNSリンクは任意。 |
| E | 美容院について | コンセプト、店舗の特徴、接客や店内の雰囲気、店内写真。 |
| F | 店舗情報・アクセス | 店名、住所、営業時間、定休日、電話番号、アクセス説明、地図リンク。駐車場等の追加情報を掲載できる。 |
| G | 予約 | 電話、外部予約サービス、LINEまたはSNSへの案内。予約方法ごとに表示、説明、リンク、表示順を設定できる案とする。 |
| H | お知らせ | タイトル、本文、掲載日。分類、画像、掲載終了日を設定でき、ホームに最新情報を表示できる。 |
| I | ヘアケア・美容コラム | 記事本文、タイトル、公開日、画像、分類。執筆スタッフや関連メニューへのリンクは任意。 |
| J | よくある質問 | 質問、回答、分類、表示順。 |
| K | プライバシーポリシー | 本文を管理画面で編集できるページ。実際の情報利用方法に合わせた内容を掲載する。 |

ページ種別は11種類とする。お知らせとコラムには一覧・詳細の両方を設けるため、モックアップでは合計13種類の画面テンプレートを扱う。

### ナビゲーション案

- ヘッダーには、ヘアスタイル、メニュー、スタッフ、美容院について、お知らせ、コラム、店舗情報を配置する。
- 予約ボタンを目立つ形で設ける。
- ホームはロゴから移動できるようにする。
- よくある質問とプライバシーポリシーはフッターに配置する。

## 3. WordPress管理とテーマのカスタマイズ

### 決定

- 店舗情報、メニュー、スタッフ、スタイル写真、お知らせ、コラム、FAQ、各ページの文章・画像、予約先はWordPress管理画面から編集できるようにする。
- 画像には管理画面から代替テキストを設定できるようにする。
- ページ本文、繰り返し登録する情報、共通の店舗情報を適切に使い分ける。
- WordPress標準機能を基本とし、必要な機能だけ保守されているプラグインを追加する。
- テーマ固有の見た目の調整項目は必要な範囲に絞る。

### テーマ側の調整候補

- ロゴ
- 配色
- ヘッダー・フッター
- ホームのセクション表示と順序
- アニメーション設定

店舗の内容・文章・写真をテーマに固定せず、テーマを変更してもサイト固有の情報を引き続き管理できる構成を目指す。具体的な編集画面、保存方式、データ構造、プラグイン選定は技術設計で決める。

## 4. デザイン・操作性

### 決定

- 全体の雰囲気はナチュラルで親しみやすい。
- 基調色はアイボリー、ベージュ、温かみのあるブラウン。
- 見出しは上品に、本文は読みやすくする。具体的な書体は後工程で選ぶ。
- ヘアスタイル写真と店内・スタッフ写真を組み合わせる。
- ホームは写真を印象的に見せ、各ページは情報を整理する。
- スマートフォンを優先して設計する。
- Claude向けモックアップはA〜Kの全11ページを対象とする。全ページをレスポンシブにし、ホームと代表的な下層ページはスマートフォン・PCの両方で重点確認する。
- ホームの最初の画面ではヘアスタイル写真を主役にし、主ボタンは「ヘアスタイルを見る」、副ボタンは「予約する」とする。
- 表示演出として、スクロール時の表示、背景の奥行き、横送りのスタイルギャラリーを組み合わせる。
- 端末で動きを減らす設定が有効な場合はアニメーションを控える。

### 要件上の留意点

アニメーションは選択したデザイン表現として扱う。操作や情報理解を妨げず、動きを減らす設定でも主要な情報と機能を利用できるようにする。

## 5. アクセシビリティ、パフォーマンス、検索

### アクセシビリティ

基本的な使いやすさを満たす。文字の読みやすさ、キーボード操作、画像の説明、見出し構造、動きを減らす設定への配慮を含める。特定の適合基準・適合レベルは未決定。

### パフォーマンス

基本的な高速化を行う。画像のサイズと容量を調整し、画面に応じた画像を使い、画面外の画像は必要なタイミングで読み込む。数値目標は未設定。

### 検索対策

基本的な検索対策を含める。ページごとのタイトル・説明、店舗情報、画像の説明を管理できるようにする。アクセス解析ツールは今回の初期要件に含めない。

## 6. 予約、個人情報、管理権限

- サイト内の問い合わせフォーム・予約フォームは設けない。
- 電話、外部予約サービス、LINEまたはSNSへ案内する。これらは希望候補であり、実際に使う方法とリンク先は未確定。
- 担当者ごとにWordPressアカウントを作成し、必要な編集権限だけ付与する。
- 外部の予約サービスやSNSが個人情報を扱う場合、プライバシーポリシーの記載内容は実際の運用を確認して決める。

## 7. 技術・対応環境

- テーマ形式はクラシックテーマ。
- 文書記載のLocal環境、WordPress 7.1.3・PHP 8.2.29を実装確認の基準とする。
- この基準は本番環境の最低対応バージョンを決めるものではない。本番環境と最低対応バージョンは公開先に合わせて確認する。
- スマートフォン・PCの主要ブラウザを対象とし、具体的な対応ブラウザとバージョンは公開前に決める。
- プラグインはWordPress標準機能を基本とし、必要なものに限る。
- 開発環境の記載値はプロジェクト文書に基づく。実稼働環境の状態はこの要件書では検証していない。

## 8. テスト、公開、運用

次の事項は公開先が決まった後に決定する。

- 公開前に確認する端末・ブラウザ・ページ・機能の範囲
- ステージング環境の有無、公開手順、公開後の確認方法
- WordPress・PHPの本番対応範囲
- WordPress本体・プラグインの更新担当と頻度
- バックアップの方法・頻度と復元手順

## 9. 開発体制

現行 `AGENTS.md` に従う。

- ChatGPT Work: プロジェクト管理、技術設計、コードレビュー
- Claude: 静的HTML/CSS/JavaScriptによるデザインモックアップ制作
- Cursor: 主な実装
- 人間: タスク開始、デザイン、レビュー結果、最終変更の確認。Gitクライアントでの差分確認、コミット、プッシュ

デザインモックアップは人間の確認・承認後に実装へ反映し、テーマ本体へそのままコピーしない。

## 10. 次の作業案

デザインモックアップは作成済みで、ユーザー確認により完成とする（[`design-mockup/README.md`](../design-mockup/README.md)）。以後は承認済みデザインを基準として、テーマ用に設計・実装し直す。

1. 管理画面で扱う店舗情報・メニュー・スタッフ・スタイル・ヒーロー画像等のデータ項目と編集の流れを技術設計する。WordPress標準のコンテンツ管理とテーマカスタマイズの責務を分ける。
2. クラシックテーマの構成、テンプレート、データ連携、画像登録・表示、アクセシビリティとパフォーマンスの実装方針を決める。
3. 公開環境、本番互換性、ブラウザ範囲、更新・バックアップ、テスト・リリース方針を決める。
4. 合意した設計と要件に基づいてテーマを実装し、検証する。
