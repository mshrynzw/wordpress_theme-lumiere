# LUMIÈRE ドキュメント

## 目的

このディレクトリは、LUMIÈRE の設計、タスク、レビューの記録を管理します。ChatGPT Work、Cursor、Claude の会話内容が共有されるとは限らないため、リポジトリ内の文書を AI と人間の共通情報源にします。

## 構成

- `requirements.md`: サイト要件の合意事項と未決事項。
- `tasks/`: タスク一覧と個別タスク文書。運用方法は `tasks/README.md` を参照。
- `reviews/`: 実装レビューの指摘、対応状況、再確認結果。
- `architecture/`（必要になった時点で作成）: 設計概要や分野別設計。
- `architecture/decisions/`（必要になった時点で作成）: 影響の大きい設計判断とその理由。

不要な空ディレクトリや文書を先回りして増やさず、必要になった時に追加します。

## 決定事項と未決事項

合意され、現在有効な内容は設計文書に「決定」として記載します。候補、前提未確認、選択待ちは「要確認」または「未決」と明示し、決定事項と混在させないでください。重要な判断を変更する場合は、影響する文書と関連タスクを更新し、必要なら判断記録を残します。

現在把握している開発環境は、Local、WordPress 7.1.3、PHP 8.2.29、nginx、MySQL 8.4.0 です。テーマ形式はクラシックテーマと決定しています。対象環境・ブラウザ、機能・デザイン要件など、その他の未決事項は要確認です。開発体制は ChatGPT Work がプロジェクト管理・技術設計・コードレビュー、Claude がデザイン案作成、Cursor が実装を担当し、人間が Git クライアントで差分確認・コミット・プッシュを行います。

## 情報の優先順位

1. 人間が確認・承認した最新の要件と決定事項
2. 現在のタスク文書の受け入れ条件と範囲
3. 最新の設計文書・判断記録
4. `AGENTS.md` と `.cursor/rules/` の作業規則
5. 既存実装と過去のレビュー記録
6. AI の会話内の提案や推測

文書同士に矛盾があれば、独断で解消せず矛盾箇所を示して人間に確認します。会話で決まった内容も、共有すべき決定なら該当文書に反映してから共通前提として扱います。

## 更新方針

- 文書は簡潔に保ち、実装と合わなくなったら同じタスク内で更新します。
- タスクは `tasks/README.md` の形式を使います。レビュー記録からは対象タスクと変更を追えるようにします。
- 設計上の大きな選択は、選択肢・理由・影響が後から分かる形で記録します。
- 未確定事項は要確認のまま残し、確認担当または確認時期が決まっている場合はそれも記載します。
- 秘密情報、認証情報、不要な個人情報を記載しません。
